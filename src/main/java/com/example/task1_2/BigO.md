
| Операция | Средняя | Худшая |
|---|---------|---|
| `put(K, V)` | O(1)*   | O(n) |
| `get(K)` | O(1)    | O(n) |
| `remove(K)` | O(1)    | O(n) |
| `resize()` | O(n)    | O(n) |


Обоснование:
1. **Средняя O(1)** — потому что при превышении load factor количество бакетов расширяется, поэтому средняя длина списков остаётся небольшой.
    При равномерном распределении хешей операции get, put и remove выполняются за константное время в среднем, так как работают только с одним бакетом.
2. **Худшая O(n)** — Если все ключи из-за коллизий оказываются в одном бакете, то структура вырождается в связный список длины n, и операции put, get, remove становятся линейными по времени.
    resize() в любом случае надо обработать все элементы, поэтому у него всегда линейная сложность.
3. **put(K,V) = O(1)** - если при этом не происходит resize().
